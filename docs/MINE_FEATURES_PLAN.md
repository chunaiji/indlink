# 「我的」功能完善规划

> 目标:把「我的」页其它功能从占位/toast 落地为可用功能。按"后端依赖 + 价值 + 工作量"分批。

| 功能 | 现状 | 后端 |
|---|---|---|
| 真人认证 | ✅ 已实现(提交即认证) | `POST /user/verify` |

## 分批计划

### 批次 A — 后端已就绪,纯前端(本轮实现)
1. **道具商城页** `pages/items/items`:展示 `/item/list`,选道具 → `/item/buy` 扣金币;余额不足引导充值。从「我的」道具商城入口进。

### 批次 B — 小幅后端 + 前端(本轮实现)
2. **黑名单**:后端补 `GET /block/list`(返回拉黑的用户)+ `POST /block/remove`(解除);前端 `pages/blocklist/blocklist` 列表 + 解除按钮。
3. **浏览记录**:复用 relation `viewed`,后端补 `GET /relation/viewed-list`(我看过谁,带用户卡片);前端复用 `user-avatar` 列表页。
   - 注:现有 `/relation/list?type=viewed` 返回的是"谁看过我";"我看过谁"需新增 `i-viewed` 维度。

### 批次 C — 需新建后端 + 产品决策(待定,重大分歧时再确认)
4. **我的收藏**:需新增 `collection` 表 + 收藏/取消/列表接口 + 在捞瓶/详情加收藏入口。属新功能,工作量中等。
5. **我的动态(Moments)**:需新增 `moment` 表 + 发布/列表/点赞 + 动态广场页。属较大功能,建议作为独立里程碑。

## 决策点(需你拍板的)
- **收藏 / 动态** 是否纳入近期范围?二者都要新建后端表与接口,且动态是较大模块。默认我**先不做**,放进后续里程碑;你要现在做就说一声。
- 浏览记录语义:默认实现"**我看过谁**"(更符合"浏览记录"直觉)。
