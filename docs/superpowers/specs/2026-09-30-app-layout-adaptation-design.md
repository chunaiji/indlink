## 0. 结论先行

**核心模型：以逻辑像素为单位、以 375pt 为设计基准、以约束布局吸收尺寸差异；绝不整页等比缩放。**

五条铁律，违反任何一条视为 UI bug：

1. 字号、间距、圆角、图标尺寸、按钮高度**只用 `Dim` 刻度，永远不乘屏幕比例**。
2. **宽度决定布局，高度只决定装饰区收缩**。任何页面不因高度切换布局。
3. 同一套手机布局必须在 **360×780** 上不溢出、不换行错位；360 是正常手机，不是特例。
4. SafeArea、键盘 insets、文字缩放钳制、竖屏锁定**在 App 根与 Shell 各做一次**，页面不重复处理。
5. 装饰性整屏画面（海面、引导插画、捞瓶仪式）走 **设计画布** 等比缩放；画布上的按钮和文字不在画布内，仍走铁律 1。

## 1. 背景与问题

原型 `v2-screens.html` 的手机框是 252×512 CSS px，注释明确"屏宽 252px 对应 375pt，比例 0.672"。还原后它是一张 **375×762pt 的固定画布**。`tokens.dart` 已把 `--t* / --r* / --s*` 还原为 pt 值，方向正确。

在小米 9（逻辑 393×851）上实测观感是"放大版原型，不自然"。逐项归因如下，均与物理分辨率无关：

| # | 来源 | 现状 | 影响 |
|---|---|---|---|
| 1 | 比对基准不公平 | 原型在显示器上按 252px 缩略展示，比真机小 1.49 倍 | 任何 App 上真机都显得"粗" |
| 2 | Material 3 默认密度 | `theme.dart` 未设 `visualDensity` 与 `materialTapTargetSize` | 按钮 48、列表行 56、图标按钮 48，比原型 44 大约 10% |
| 3 | 中文字体行高 | `_textTheme` 的标题类样式未给 `height`，行高由设备字体决定 | 小米 MiSans、华为 HarmonyOS Sans、Noto CJK 的 ascent/descent 比 PingFang 大，每行高出 2～4pt |
| 4 | 系统字体缩放未钳制 | 无任何 `textScaler` 处理 | MIUI/EMUI 用户开大字体后全 App 放大 1.15～1.3 倍 |
| 5 | 高度轴无规则 | 海面页装饰按容器高度百分比定位 | 667 高挤成一团，932 高空一大块 |

**物理分辨率（1080×2340 与 1179×2556）只影响图片清晰度，不影响排版**。Flutter 的逻辑像素已经抹平了 DPI 差异。

## 3. 核心模型：四层各做一次

自适应逻辑按它"住在 widget 树哪一层"组织，每件事只在一处做，页面不重复。

| 层 | 位置 | 只做这些事 |
|---|---|---|
| **App 根** | `MaterialApp.router` 的 `builder` + `main.dart` | 文字缩放钳制；竖屏锁定；edge-to-edge 与系统栏样式 |
| **Shell** | `app/shell.dart` | 按窗口宽度判定一次：宽 ≥ 600 内容限宽 480 居中；底部 Tab 栏的安全区 |
| **页面** | 各 `*_page.dart` | 顶部 SafeArea；键盘 insets；固定区 / 弹性区 / 可滚动区的划分 |
| **组件** | `ui/widgets/*`、场景画布 | `LayoutBuilder` 按父容器空间排布（网格列数、画布缩放） |

判定规则：

- **"用哪种布局"在 Shell 用 `MediaQuery.sizeOf(context).width` 判一次**。页面里不再出现宽度断点判断。
- **`LayoutBuilder` 只用于组件按自身空间排布**，不用于判断设备类型。父容器约束已被 SafeArea 和 Padding 扣过，同一个阈值在不同页面结果不同。
- 断点常量集中在 `tokens.dart` 的 `Breakpoints`，禁止在页面里写数字。

## 4. 尺寸体系

### 4.1 单位与刻度

- 一切尺寸单位是逻辑像素（Flutter 的 `double`，iOS 叫 pt，Android 叫 dp）。
- 字号 8 档、圆角 6 档、间距 4pt 栅格，全部来自 `Dim`。**页面代码里不允许出现 `Dim` 以外的字号与间距字面量**，需要新档位先改 `tokens.dart`。
- 禁止引入 `flutter_screenutil` 或任何"设计稿宽度 ÷ 屏幕宽度"的缩放方案。它在 430 宽的机器上把一切放大 15%，正是"放大版"观感的来源，且让系统无障碍字体失效。

### 4.2 宽度轴

| 区间 | 处理 |
|---|---|
| 360～599 | 同一套手机布局。内容区两侧 `Dim.gutter`（16），卡片和列表行横向拉伸填满 |
| ≥ 600 | Shell 把内容列限宽 `Breakpoints.contentMaxWidth`（480）居中，两侧留白；底部 Tab 栏保持全宽 |

- 文字必须能换行或截断，禁止假设"这行在 375 上能放下"。按钮文案在 360 宽、缩放 1.2 下不得换行，做不到就缩短文案。
- 横向并排的元素用 `Expanded`/`Flexible` 分配，禁止写死两个并排元素的绝对宽度之和。
- 折叠屏展开态和平板 **V1 不做双栏**，只做限宽居中。双栏（聊天列表 + 聊天室）列为后续项。

### 4.3 高度轴

每个页面把纵向内容划为三种区域，并在页面文件头部注释登记：

| 区域 | 含义 | 规则 |
|---|---|---|
| 固定区 | 导航栏、Tab 栏、底部主按钮、输入栏 | 高度固定，永不压缩 |
| 弹性区 | 装饰性画面、空态插画、大标题上方留白 | 吸收多余高度；高 < 700 时进入收缩态 |
| 可滚动区 | 列表、表单、长文 | 内容超出即滚动，是高度差异的默认出口 |

- 一个页面**至少有一个弹性区或可滚动区**，否则它在 667 或 932 上必然出错。
- 弹性区用 `Expanded`/`Spacer`/`Flexible` 表达；禁止按容器高度百分比 `Positioned` 功能控件。装饰元素允许百分比定位，但只在设计画布内（§5）。
- 矮屏收缩态（高 < 700）：弹性区最小高度、插画缩小或隐藏、大标题上方留白减半。收缩态**不换布局、不换页面**。
- **高屏多余高度的去向**必须在页面登记里写明。表单类整屏页（登录）默认规则：多出的高度按 **1:2** 分到头部上方与底部，表单整体略靠上居中。原型按 762 高的框画的，851 以上机器多出 100～250pt，不写去向就会全堆在一处。实现用 `CustomScrollView` + `SliverFillRemaining(hasScrollBody: false)` + `Spacer`，内容超出一屏时两段留白自动归零再滚动，键盘弹起同理。**只能用 `Spacer`**：`Flexible` 包固定高度的 `SizedBox` 会把那段高度算进 Column 固有高度，页面会平白多出一截可滚动区。

### 4.4 安全区与 insets

两个概念分开处理，禁止混用：

| 名称 | Flutter 取值 | 含义 | 谁处理 |
|---|---|---|---|
| 安全区 | `MediaQuery.viewPaddingOf` | 刘海、挖孔、状态栏、底部 home 条、三键导航栏 | 顶部：页面 `SafeArea(bottom:false)`；底部：Shell 的 Tab 栏或页面底部按钮 |
| 键盘 | `MediaQuery.viewInsetsOf` | 软键盘弹起占用的高度 | 有输入框的页面：`Scaffold.resizeToAvoidBottomInset` 或底部栏 `AnimatedPadding` |

- 底部固定按钮的下方 padding = `max(viewPadding.bottom, Dim.s4)`，三键导航（48dp）与手势导航（16～34）都要实测。
- 聊天页、登录页、发瓶页、评论输入是键盘 insets 的必测页面。印度低端机键盘高度可达屏幕 45%，键盘弹起后输入栏必须仍可见，上方内容可滚动。
- Android 15 起系统默认 edge-to-edge，App 根统一 `SystemUiMode.edgeToEdge` 并设透明系统栏；页面靠 SafeArea 避让，不依赖系统自动加 padding。

### 4.5 文字缩放

- App 根 `builder` 中把 `MediaQuery.textScaler` 钳制在 **0.9～1.2**。
- 钳制后仍需保证：360 宽 × 缩放 1.2 下所有按钮文案不换行、列表行不溢出。
- 禁止在页面里再包一层 `MediaQuery` 覆盖缩放，禁止 `textScaler: TextScaler.noScaling`（无障碍投诉来源）。

### 4.6 行高与字体

- `_textTheme` 中**每一档样式显式给 `height`**：标题类 1.25，正文 1.6，次要与辅助 1.5。不允许依赖字体默认行高。
- 设置 `TextHeightBehavior(leadingDistribution: TextLeadingDistribution.even)`，上下留白均分，中文与英文混排基线一致。
- **打包一套字体**，三地区渲染一致：中文 MiSans 或 HarmonyOS Sans（两者均允许商用），英文与数字用同一家族的 Latin 子集。子集化后每字重控制在 4MB 内，只打包 Regular / Medium / Bold 三档。字体选型在实施计划里定，本文只定"必须打包"。
- 印度地区若后续支持印地语，天城文字形更高，行高需要单独档位，本文不覆盖。

### 4.7 Material 密度

`theme.dart` 补三项，把 Material 3 默认尺寸收到原型的 44pt 体系：

| 项 | 值 | 效果 |
|---|---|---|
| `visualDensity` | `VisualDensity.compact` | 按钮、列表行、输入框各减 4pt |
| `materialTapTargetSize` | `MaterialTapTargetSize.shrinkWrap` | 不在控件外再撑 48dp 透明区 |
| 各按钮 `minimumSize` | 高 `Dim.tap`（44） | 与原型一致 |

可点区域下限仍是 44，`shrinkWrap` 只去掉控件外的透明撑高，不允许把可点区做到 44 以下。

### 4.8 屏幕方向

- **手机锁竖屏**（`DeviceOrientation.portraitUp`），在 `main.dart` 设置。
- 折叠屏展开态与平板 V1 同样锁竖屏。放开横屏是独立需求，需要重新走设计。
- 图片查看器（`image_viewer.dart`）例外：允许横屏查看，退出时恢复竖屏。

### 4.9 折叠屏与平板

- 折叠屏折叠态就是普通手机，走 360～599 规则。
- 展开态按 ≥ 600 处理：限宽居中。展开与折叠切换时窗口尺寸会变，Shell 的判定必须是响应式的（每次 build 重新取 `sizeOf`），不能缓存。
- 铰链、双屏分栏 V1 不处理。

### 4.10 图片与资源

- 图片解码尺寸按逻辑宽度 × 设备像素比限制（`cacheWidth`），列表缩略图不得解码原图。印度 3～4GB 内存机型是此规则的验证机。
- 图标用矢量或 `Icons`，位图图标按 2x / 3x 提供，不提供 1x。
- 1pt 分割线用 `AppColors.line` 并允许亚像素渲染，不追求物理像素对齐。

## 5. 设计画布（DesignCanvas）

装饰性整屏画面（海面 B1、引导页插画、捞瓶仪式）是原型最难对齐的部分，用画布一次解决。

> 登录页在 v2 原型（A2）里没有背景画面，它是表单页，走 §6 的表单页规则，不进画布。

### 5.1 定义

- 画布锚定原型坐标系 **375×762**。画布内所有装饰元素（太阳、云、灯塔、浪线、漂浮的瓶子）用原型坐标定位，不再用容器百分比。
- 画布**按宽度等比缩放**：缩放系数 = 可用宽度 ÷ 375。高度不足时**裁剪底部**（海水），高度多余时**底部延伸海水渐变**填满。
- 画布只承载装饰。**按钮、文字、头像、金币等功能控件不放进画布**，它们作为画布的兄弟节点，走 `Dim` 刻度与 SafeArea。

### 5.2 组件接口

```dart
/// 装饰画布：原型 375×762 坐标系，按宽度等比缩放，高度不足裁底、多余延伸。
class DesignCanvas extends StatelessWidget {
  const DesignCanvas({
    super.key,
    required this.children,      // 用 CanvasPositioned 按原型坐标定位
    this.designSize = const Size(375, 762),
    this.extendBottom,           // 高度多余时底部填充（如海水渐变）
  });
}

/// 原型坐标定位，内部换算为缩放后的实际坐标。
class CanvasPositioned extends StatelessWidget {
  const CanvasPositioned({required this.left, required this.top, required this.child, ...});
}
```

### 5.3 迁移页面

| 页面 | 现状 | 迁移后 |
|---|---|---|
| 海面 B1 / B1n | `sea_scene.dart` 用 `LayoutBuilder` 按高度百分比定位 | 装饰迁入画布；捞瓶按钮、头像、金币在画布外 |
| 引导页 | 插画 `width: 104` 写死 | 插画入画布；文案与按钮在画布外 |

夜场（`night`）与系统暗色仍是两根独立的轴，画布只换素材不换坐标。

## 6. 页面分类与伸缩规则

每个页面归入一类，按该类的默认规则实现；例外必须在页面文件头注释说明。

| 类别 | 页面 | 固定区 | 弹性区 | 可滚动区 |
|---|---|---|---|---|
| 场景页 | 海面、引导、捞瓶仪式 | 顶栏、底部主按钮 | 设计画布 | 无 |
| 列表页 | 发现、动态、聊天列表、我的瓶子、礼物墙 | 顶栏、筛选条 | 无 | 列表本体 |
| 表单页 | 登录、注册 / 找回密码、资料编辑、发瓶、充值、设置 | 顶栏、底部提交按钮或协议 | 头部留白（登录页，矮屏减半）；登录页多余高度按 1:2 分到头部上方与底部 | 表单本体 |
| 聊天页 | 聊天室 | 顶栏、输入栏 | 无 | 消息列表（倒序） |
| 详情页 | 瓶子详情、动态详情、用户主页 | 顶栏、底部操作栏 | 头图（矮屏收缩） | 正文 |
| 弹层 | 送礼、支付、确认 | 标题、按钮 | 无 | 内容超出即滚动，最大高度 = 屏高 × 0.85 |

弹层补充：底部弹层高度由内容决定，设 `maxHeight` 而非固定高度；顶部圆角 `Dim.r5`；底部 padding 含 `viewPadding.bottom`。

**导航层级与 Tab 栏**（2026-10-04 真机返工补入）：只有五个 Tab 根页（海面 / 发现 / 消息 / 动态 / 我的）带底部 Tab 栏；
Tab 根之下的任何一级（写瓶、详情、筛选、资料、发动态、选地点、钱包……）都是全屏页，路由必须挂
`parentNavigatorKey: rootKey`，`test/app/router_test.dart` 守着。少挂一个，那一页就在 Tab 栏上方少 65pt，
底部按钮挤在 Tab 栏之上——这是第二批小米 9 截图里六个页面共同的"不像原型"。

**组件自收缩**：胶囊 / 标签 / 小按钮一律按内容收缩，不得依赖父级给的约束——`Container(alignment:)`
在有界约束（`Wrap`、`Column`）里会撑满整行，横向 `SingleChildScrollView` 在 `Column` 里会被居中。
写新组件时用 `Center(widthFactor: 1)` / `SizedBox(width: double.infinity)` 显式表达意图，并在 `Wrap` 里加一条宽度测试。

**页面登记格式**（写在页面文件头部注释）：

```
/// 类别：场景页
/// 固定区：顶栏 / 捞瓶按钮
/// 弹性区：海面画布（高 < 700 时裁底）
/// 可滚动区：无
/// 键盘：无
```

## 7. 代码落点与约定

### 7.1 文件

### 7.2 禁止事项

- 禁止 `flutter_screenutil` 及任何比例缩放单位。
- 禁止页面内写宽度断点数字；禁止页面内用 `LayoutBuilder` 判断设备类型。
- 禁止功能控件按容器百分比 `Positioned`。
- 禁止 `TextScaler.noScaling`。
- 禁止 `Dim` 之外的字号与间距字面量（图片尺寸、动画位移除外）。
- 禁止固定高度的底部弹层。
- 禁止把并排元素的宽度写死。

2. 没有 §7.2 的禁止项。
3. golden 测试矩阵（§8.2）全部通过，或附了更新后的基准图与理由。

## 8. 验证

### 8.1 公平比对方法

改布局前先建立正确的比对基准，否则一切调整都是凭感觉：

1. Chrome 设备模式设为 393×851、DPR 2.75（小米 9）。
2. 给原型的 `.ph` 临时加 `zoom:1.488`（375 ÷ 252），让原型按真实 pt 渲染。
3. 真机截图缩放到 393 CSS px 宽，与原型并排。
4. 逐项量：控件高度、行高、间距、字号。差异归入 §1 的五个来源之一再改。

### 8.2 golden 测试矩阵

`test/golden/` 下对每个场景页与每类页面的代表页面，固定以下配置生成基准图：

| 配置 | 尺寸 | 文字缩放 | 覆盖 |

| narrow | 360×780 | 1.0 | 印度 Redmi、三星默认 |
| short | 375×667 | 1.0 | iPhone SE，矮屏收缩态 |

每次改布局跑全量；基准图变更需在 PR 里附前后对比。

现状（2026-10-03）：布局矩阵覆盖全部页面（`test/layout/all_pages_test.dart`，各分节一个文件，聊天室 / 写瓶 / 发动态另加键盘变体，海面另加三键导航变体）；海面夜场 × 暗色四组合有 golden；其余页面的像素级 golden 待补。每条失败都会打印溢出控件的 file:line。

## 9. 地区性风险登记

这些不是布局问题，但会在三个目标地区直接影响 App 能否使用，需要单独决策：

| # | 风险 | 影响地区 | 说明 |
|---|---|---|---|
| R1 | 华为新机不运行安卓 APK | 中国 | Mate 70、Pura 70 之后为 HarmonyOS NEXT，Flutter 只有社区版 OpenHarmony 移植。**已决策不纳入**（D8），华为只覆盖仍运行安卓的存量机型 |

## 10. 决策记录

| # | 决策 | 结论 | 理由 |
|---|---|---|---|
| D1 | 缩放策略 | 固定 pt + 约束布局，场景画布局部等比 | 整页等比是"放大版"观感的来源，且破坏无障碍 |
| D2 | 宽度断点 | 只有 600 一个，≥ 600 限宽居中 | 30 多个页面养不起多套布局；无桌面目标 |
| D3 | 360 以下 | 不设独立布局 | 360 是正常手机，手机布局必须在 360 上成立 |
| D4 | 屏幕方向 | 手机、折叠屏、平板 V1 全部锁竖屏 | 少一整个维度的测试面；图片查看器例外 |
| D5 | 文字缩放 | 钳制 0.9～1.2 | 尊重无障碍但不允许撑破布局 |
| D6 | 字体 | 必须打包，选型在实施计划定 | 不打包就永远在四种中文字体上飘 |
| D7 | 折叠屏双栏 | V1 不做 | 列为后续项 |
| D8 | 华为 HarmonyOS NEXT | 不纳入目标机型 | 2026-09-30 决策；需要独立的 OpenHarmony 构建链，不在本期 |
