One key difference from the mini-program: In the mini-program, tab visibility comes from GET /api/tabs is pushed remotely to switch between tool mode and social mode. The app needs no such review disguise —all 5 tabs are permanent. But /api/features feature flags are worth keeping for staged rollout and emergency shut-off.
The phone screens are drawn to a scale you can convert straight to device points. 252px here maps to a 375pt device, a ratio of 0.672; the page's CSS variables --t* / --r* / --s* carry the matching pt value in a comment. Type sizes are only 11 / 12 / 13 / 15 / 17 / 20 / 24 / 28; corner radius is tiered by element 8 chips · 12 buttons · 16 cards · 20 panels · 28 modals · 999 pills; spacing follows a 4pt grid, with a uniform screen gutter of 16pt so everything lines up on one vertical edge. Minimum tap-target height is 44pt — list rows, buttons and tabs all honour that floor. Fully rounded pills have a second floor — an aspect ratio of at least 1.7 : 1 — a minimum width alone is not enough. A one-character chip (M, F) at 30px by 22px is only a 1.35 ratio, and with border-radius:99px still reads as a circle. So .cp / .ch use min-width:44px plus 12px horizontal padding, measured at roughly 1.8 : 1. The swipe deck is the one exception, deliberately a notch wider than the body gutter.
Button colour carries meaning. It is not a styling choice. Four levels, fixed across the app: Solid aqua = free actions on the main path (pull, throw, sign in, claim check-in coins) · solid pink = costs coins or real money(unlock, say hi, gift, top-up) · grey outline = secondary · solid warning = destructive (report and block). A secondary action that costs money uses a pink outline, so "pink means it costs money" holds at every level. Gradients are reserved for brand surfaces (headers, the active tab pill, progress bars);buttons are always solid. The direct result:there is no pink anywhere in the Ocean screen's content area — that is not a coincidence, it tells people the sea is free. The active tab pill is the one exception: it belongs to the global shell rather than the sea. Using the brand colour for the active tab is a universal convention — people read it as "which page am I on", not as a price.
Tab icons are not emoji. Emoji carry their own colour, which looks dirty on a coloured active pill, and the inactive state needs grayscale + opacity to grey them out, which leaves a shapeless blur. The same emoji also renders differently on different machines — while building this page, 🖼 rendered as a box on a test machine. Everything is now one set of line SVGs(a <symbol> sprite, referenced once across the page). Inactive is stroke-width:1.7 use --ink3; active is 2 in white. The icon vocabulary follows the product: Ocean is three waves, Discover is a compass, Moments is a four-point star.

Auth & user

Auth & User 🔨 Rework🆕 New

The existing user.resolveLogin has only wx / alipay two branches, both via code2session. The app needs four entirely new sign-in paths (phone, email, Google, Apple), and model.User is missing email, password_hash, language, interests and lat/lng.

Day-to-day sign-in is by password; codes are only for sign-up and password reset. Phone keeps one extra passwordless path (code signs you straight in) — that is the norm in India. Codes must be purpose-bound, or a code issued for "sign-up" can be spent resetting someone else's password. See A2r.

Endpoints

One screen, two flows
Sign-up and password reset have identical shape (identifier → code → set password) and differ only in title, button label and which endpoint they post to. The client uses a single CredentialFlowPage switched by a flow argument — writing two would duplicate the countdown and password rules
⚠️ Codes must be purpose-bound
Sending carries purpose=register|reset|login and the Redis key is otp:code:<purpose>:<identifier>. Without this, anyone who knows your email can request a code as "sign-up" and then spend it on the reset flow to take over your password. Verification requires the same purpose used when sending
State checks
purpose=register rejects an identifier that already exists; =reset rejects one that doesn't. This does reveal whether an address is registered — a deliberate trade: otherwise sign-up could only fail at submit time. Credential stuffing is held off by the three-axis rate limiting, not by hiding this
Password
bcrypt (cost 10) into User.PasswordHash, never sent down. Length-only rule of 8 — no complexity requirement: Indian users type largely on phone keypads and forcing symbols measurably hurts conversion
Gates
The code key carries purpose, the rate-limit keys do not: codes are isolated per purpose while quotas are merged per identifier, so switching purpose or channel gets you nowhere

Three modules with no app UI

Fraud · Admin · Analytics

These three produce no app UI, but they all need technical design. Don't let "there's no mockup" drop them out of the schedule.

ModuleTodayV1 workLands in

Analytics has a hidden trap: every existing KPI is computed in UTC+8(admin/overview.go 's periodStarts, and hard constraint #4 explicitly forbids time.Now().Truncate(24h)). A third-party analytics tool defaults to UTC or the user's local zone, the two datasets' "today" are different days, and reconciliation will produce contradictory numbers. For India you then stack IST on top (UTC+5:30, with a half-hour offset). Pin the time-zone definition before you instrument anything.

Gestures & motion

Gestures & motion 🆕 Front-end only

If a static mockup doesn't state the gesture and the duration, everyone invents their own and the app ends up with no rhythm. These are values Flutter can use directly. One rule throughout: animation that answers a user action must be fast (≤300ms); decorative animation that plays on its own must be slow and switchable.

SceneGesture / triggerAnimationNotes
C1 swipe Horizontal drag, distance > 25% of screen width or flick speed > 800 px/s commits; otherwise it springs back 1:1 with the finger; rotation = distance × 0.06° (max 12°); fly-out easeOutCubic 280ms, spring back spring(0.6, 18) The commit test needs both distance and velocity; distance alone kills quick flicks, velocity alone kills slow drags
C1 stamp Fades in live during the drag Opacity maps linearly to distance, 0→1, full at 25% Full opacity at the threshold lets people know the outcome before they let go — the single most important feedback in a swipe deck
B1a pull ritual Press and hold and drag down > 30pt to commit. Release early and the bottle sinks back without spending a pull Ripples 2.6s ease-out three rings out of phase; the bottle rises with rise 2.6s ease-in-out; on release the bottle scales up and fades over 220ms, and the letter scaleY 0.3→1 easeOutCubic 340ms Fire the request the instant they press, so animation and network run in parallel. 2.5s covers a weak connection and nobody perceives loading — this is the standard way to hide a loading state inside a ritual
B1 tappable sea Tap a bottle for a bubble; drag > 60pt for high-tide refresh; tap the lighthouse for the sea report The bubble spring(0.7,20) 240ms pops from the bottle neck; high tide lifts the sea translateY 12pt then settles back The bubble does not spend a pull.
