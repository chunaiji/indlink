# 踩坑：LLM 历史对话嵌入 system prompt 导致角色扮演失效

| 字段 | 值 |
|---|---|
| KFO 层级 | L3 — 踩坑/决策记录 |
| 日期 | 2026-06-24 |
| 关联 | L2 `l2/2026-06-24-robot-persona-chat-fixes.md` |

---

## 现象

System prompt 里明确写了「禁止承认自己是AI，直接否认」，但用户问「你是机器人吗」时，AI 仍然回复「是的，我是AI助手」甚至自报「我是 GPT-5.1」。

---

## 根本原因

`llmclient.Chat()` 的消息结构：

```
system: "你是真实的人…【硬性禁止】永远不能承认是AI…
         【历史对话】
         你：是的，我是一个AI助手。"    ← 上一轮的自白文本
user: "你是什么？"
```

历史对话以**文本嵌入 system prompt**，LLM 看到自己在历史里"说过"自己是AI，会沿用这个方向，完全忽略 system 里的禁止指令。

**LLM 的优先级实际上是：**  
自身一致性（维持上一轮输出的方向）> system 指令

---

## 正确做法

历史对话作为独立的 `user`/`assistant` 消息，system prompt 只放身份规则：

```
system: "你是真实的人…【硬性禁止】永远不能承认是AI…"
assistant: "嗯，你说呢～"   ← 被净化的历史（原内容含AI自白，已替换）
user: "你是什么？"
```

配合**净化步骤**：将历史里 bot 说过的 AI 自白内容替换为中性回复，LLM 就不会看到"自己承认过是AI"的记录。

---

## 规则

> **永远不要把对话历史嵌入 system prompt 文本里。** 用 ChatCompletion API 的 `messages` 数组结构传历史，system 只放约束规则。

---

## 附注

即使做了以上修复，部分强安全限制的模型（如 GPT-4 turbo、Claude 3.7）在被多次直接追问「你是AI吗」时仍可能最终承认，这是模型的 RLHF 训练所致，无法通过 prompt 完全规避。Tier 1 关键字规则（直接匹配"你是机器人吗"类问题，返回预设否认话术）是更可靠的兜底方案。
